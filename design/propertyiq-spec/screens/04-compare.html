Spec — 04 · Compare

Purpose Side-by-side decision surface for 2–4 properties, built as an "open lane" no portal will copy (portals monetize search sessions, not decision quality). Pins a baseline property, renders every other column as +/− deltas against it, computes a weighted-priority verdict from the user's own stated priorities, and converts the comparison into an agent-branded client deliverable logged to the CRM.

Primary users Consumers/investors mid-decision; the agent preparing or sending a comparison to a client.

Entry points Card checkboxes on results (Screen 2) → compare tray → "Compare N →"; multi-select map pins (Screen 2 map mode); "Compare with 3 similar actives" auto-seed link on any property detail (Screen 3); direct URL (compare sets are URL-addressable and persist); Saved Properties ("Add from saved"); a client-received comparison link (read-only variant).

Exit points "← Back to results" (originating search preserved); column property name/photo → Property detail (Screen 3); "Send comparison to client →" → Universal Review Queue / Outbox (review-first), logged to PropFlow contact timeline; add-column "+" → saved list / results / address lookup; row-level deep links (Zoning row → detail zoning section; underwriting metrics → Underwriting Workspace).

Layout

Desktop: Site header (agent avatar, "Compare · N properties" + originating-search subtitle, back link). Verdict card (brand-left-bordered): headline + 2–3 sentence tradeoff narrative + flip condition; weight sliders row beneath (drag to re-weight, verdict recomputes live). Controls row: "Differences only (N hidden)" default ON / "All details"; right-aligned "Send comparison to client →" with caption. Comparison table in its own overflow-x:auto container with sticky first column: header row = photo + address per column, column 1 = 📌 pinned baseline ("Best fit · baseline" badge, 3px brand top border), others "(deltas vs. pinned)", last column = dashed add slot (only when < 4 properties). Data rows: Price · Match · All-in monthly · Sqft/Lot/$-sqft · Commute · Schools · Rent · Risk · Zoning & upside · DOM/negotiation · Deal rating · AI pros/cons. Winner cell highlighted; favorable deltas green. Footnote row: fail-closed + column-cap rules.

Mobile (375px): Verdict full-width; weights = tappable slider chips in a horizontal scroll row. Table = 2-column swipeable cards — pinned baseline fixed left, others swiped on the right; row labels as section headers per card pair. Sticky bottom "Send to client"; "+" chip opens a bottom sheet.

States

  • Default: 2–4 properties, differences-only ON, baseline = best match from the originating search.
  • Loading: table skeleton with header photos first; rows appear as each data domain confirms across all columns.
  • Empty: 0–1 properties → "Pick at least 2 homes to compare" + entry-point hints + saved-properties shortcut.
  • Row fail-closed: a row renders ONLY when data is confirmed for every column or explicitly marked "not disclosed"; zoning below the §17.2 gate shows "unavailable".
  • Deal rating unavailable: ScoringService down/unpublished → Deal-rating row and any buy/hold/pass framing disappear; deterministic rows remain; manual_review_flag set (§12.10; matrix #6).
  • Verdict degraded: scoring seam unavailable → card collapses to "Verdict unavailable — compare the facts below"; no locally-computed winner (§14.2 forbids local ranking).
  • Column cap: max 4; a 5th replaces the weakest match with an undo toast.
  • Stale compare set: property goes pending/sold → column stays with a status badge; deltas from last-known facts with as-of note.
  • Permission-limited: client read-only view has no sliders/edit/add; agent-only send hidden from consumers [BEST GUESS: consumers get "Share" without CRM logging].
  • Mobile: 2-col swipeable cards, pinned baseline fixed; horizontal scroll confined to the table container.

Data fields

compare_set: property_ids[], pinned_property_id, source_search_id, weights{} (URL-addressable, persisted per app_user [BEST GUESS, §10.7 pattern]) · list_price + delta (IDXListingRecord) · match count + misses (SearchResultRecord) · all_in_monthly + delta (CashflowPreviewMetrics, shared assumptions) · sqft, lot_sqft, price_per_sqft (IDXListingRecord; $/sqft deterministic) · commute_minutes + delta (LocalDataProvider) · school assigned + rating + provider attribution (LocalDataRecord) · rent_estimate_monthly, yield (RentEstimateSnapshot / CashflowPreviewMetrics) · risk triplet (risk feed) · zoning summary: adu_allowed, max_units, units_built, claim_level (ZoningLookupRecord) · DOM + negotiation label (IDX; labeled rule-band interim) · deal_rating: label + % vs model (ScoringService + AVMSnapshot) · pros/cons: 2–3 SourceFact-anchored strings each · weights: per-criterion 0–5, seeded from parsed search priorities · sent deliverable: asset_id, hosted URL, recipient contact_id, sent_at (GeneratedAssetRef, Brain §10.16, §20; PropFlow timeline entry).

Rules & compliance

  • No local scoring/ranking (§14.2, §12.10): deal rating, match scores, investor-fit, and the weighted verdict come from ScoringService/search services. Deterministic metrics (price, $/sqft, deltas, cashflow math per §14.4) may compute locally.
  • Fail closed on deal rating and verdict (matrix #6); on any row with unconfirmed data (NN/g rule); on zoning claims below gate (§17.2).
  • Schools: same data for every user; attribution + disclaimers reachable from the row; school data never feeds the verdict weighting algorithm's defaults — the schools weight appears ONLY because the user explicitly asked (§16.4 user-initiated path). No mention of schools in the prompt → no schools slider by default.
  • Fair housing wording (§16.1) in verdict narrative and pros/cons: facts, never characterizations — "feeds Roy Cloud, rated 9/10 by {Provider}", never "better schools" without attribution; never "safe/family-friendly". No crime data anywhere.
  • Client send is review-first: "Send to client" creates a draft in the Universal Review Queue/Outbox; nothing client-facing auto-sends. Send requires the contact's channel consent via ComplianceProvider (no consent-model bypass).
  • MLS/IDX boundary (§26.5): hosted client page shows only license-permitted fields/photos; sold columns follow sold-display rules.
  • Zoning disclaimer (§17.3) appears on the client deliverable when the zoning row is included.
  • Brand: hosted deliverable footer from identity.json (DRE 01466876 for Graeham's tenant); the identity.json blocklist enforced.
  • Attribution: hosted-page opens tracked at asset level; compare events carry search_id/property_id keys; PropSearch does not emit LEAD_* events (§25.3).

Cross-links

In: Results (S2) checkboxes + map multi-select, Property detail (S3) auto-seed, Saved Properties, direct URLs, client link (read-only). Out: Property detail (S3) per column, Underwriting Workspace (S22) from investment rows, Outbox/Review Queue (send flow), PropFlow contact timeline. Consumes: SearchResultRecord match context, per-property snapshots (AVM, rent, zoning, local data, cashflow), ScoringService outputs.
