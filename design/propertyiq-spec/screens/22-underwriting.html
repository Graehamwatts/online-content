Spec — 22 · Underwriting Workspace

Purpose The full "Underwrite this deal" surface for one selected property: a deterministic pro forma (income → expenses → NOI → debt → DSCR → cash-on-cash → IRR → equity multiple), an editable assumption pack with California verify-per-deal flags, ADU/BRRRR/Flip strategy overlays, three 5×5 sensitivity grids, Excel + memo exports, and run history. The heart of PropSearch (Master Brain §19) and the screen the investor persona pays for. No LLM anywhere in the math (§19.2, §12.8).

Primary users Agent (Graeham), team analysts, investor clients working with the agent (agent-driven in v1; the workspace is agent-facing, outputs are what clients see).

Entry points Property detail "Underwrite this deal" (§19.1: heavy model runs on one selected property, never inline on search rows); Zoning & Investment Intelligence panel "add to underwrite as scenario" (§17.6 — zoning Q&A and deal math are ONE surface); Compare screen per-property "underwrite" [BEST GUESS]; run history reopen (UnderwriteRunRecord); Saved Properties row → "Underwrite".

Exit points Export Excel → UNDERWRITING_XLSX (formula-driven, §20.1) → download + Asset Gallery. Client memo → UNDERWRITING_MEMO_PDF → Universal Review Queue / Outbox (Screen 24), never sends directly (§30 REVIEW_REQUIRED). "Render concept on parcel 🛰" → ADU visual flow (§17.4): Mapbox plan overlay or license-gated AERIAL_ADU. Back to property detail; run history drawer; source-fact click-through. Segment supply: runs can back a PropReach audience segment (basis UNDERWRITE_RUN §22.2) via the Audiences screen — link only.

Layout

Desktop (two-column, 1.4fr/1fr): Header — address, run badge, rent-confidence chip; nav Run history · Export Excel · Client memo (review-gated). Main column: (1) headline stat row NOI / Cap / DSCR (under-1.0 warning) / 5-yr IRR; (2) strategy overlay chips with one-line impact readout; (3) sensitivity grid card — one 5×5 heatmap visible, tabs for the other two, mandatory bear row pinned; (4) "This lot, answered (Zoneomics)" — 4 tiles + free-text lot question + disclaimer; (5) 5-year pro forma & exits table. Right rail: assumption pack, every editable assumption with source badge, verify-per-deal ⚠ badges, and the acknowledgement checkbox — sticky on scroll. No footer; exports in header.

Mobile (375px): single column — header → 2×2 stats → assumption accordion ("Edit assumptions (3 flagged)") → strategy chips (h-scroll) → sensitivity grid (overflow-x) → zoning tiles stacked → pro forma (h-scroll) → sticky bottom bar "Export" (disabled until acknowledgement, checkbox inside the export sheet) + "Recalculate".

States

  • Default: completed run displayed, live recalc on assumption edits; saved recalculation creates a new run record with new idempotency_key [BEST GUESS on save-vs-scratch].
  • Loading: skeleton stat tiles + "Running deterministic model…"; zoning panel loads independently (30-day cache TTL §12.5); stale cache → silent refresh with panel-only spinner.
  • Empty (first run): defaults pre-filled (§19.4) + region context; confirm financing (LTV/rate/term required, FinancingAssumptions §19.3) → "Run underwrite". Missing RentEstimateSnapshot → run blocked: "Rent estimate unavailable — cannot underwrite" (§19.2 forbids guessing rent).
  • Error/degraded (fail-closed §30): ScoringService down → investor-fit chip + forecast badge disappear, deterministic metrics remain, no buy/hold/pass; Zoneomics low confidence / uncovered → "Needs verification" tiles or collapsed panel, ADU chip disabled, AERIAL_ADU suppressed; IRR non-computable → null + flag, tile "—"; HOSTED_RENDER_FAILED → toast + retry, run unaffected.
  • Permission-limited: viewer-role team members read-only, exports hidden [BEST GUESS — §11.3 tenant/app-user security, no per-role UW spec].
  • Mobile: per Layout; grids and tables scroll inside their own containers.

Data fields

UnderwriteRequest ← PropertyRecord/IDXListingRecord: price, beds, baths, sqft, unit_mix (UnitMix[]), property_type. RentEstimateSnapshot §10.9 ($/mo + confidence enum + as-of). AVMSnapshot §10.10 (optional). FinancingAssumptions §19.3: ltv (0–1), rate (nominal annual), amort_term_years, points, closing_costs, rehab_budget. strategy (enum §8), hold_years (default 5). All 21 override fields (vacancy_pct … refi_costs) per §19.3 UnderwritingAssumptionOverrides. Outputs per UnderwriteDeterministicOutput §19.8: gpr, egi, per-line opex, total_opex, expense_ratio, noi_year1, going_in_cap, implied_value, GRM, loan_amount, monthly_pi, annual_debt_service, mortgage_constant, amortization rows, dscr, CFBT yr1, total_cash_in, CoC, levered_irr, equity_multiple, net_proceeds — plus underwriting_version (Brain §19.8; missing from the spec table — gap #1). Overlay fields: adu_rent/cost/incremental_noi/value_uplift/zoning_claim_level; arv/refi_ltv/new_loan/cash_out; flip profit/annualized_return + holding_costs (gap #2). sensitivity: SensitivityGrid cells. assumption_warnings, verify_per_deal_flags, manual_review_flags, source_facts, compliance_flags. memo_asset_id, spreadsheet_asset_id (asset_id never content_id).

Rules & compliance

  • LLM boundary (§12.8, §19.2): LLM allowed only for NL input parsing, memo drafting from already-computed metrics, clarification, formatting. Forbidden for any arithmetic, amortization, NOI, cap rate, IRR, local scoring/ranking, MLS embeddings. Brain §19.2 additionally forbids equity-market finance connectors and company-stock valuation model builders as arithmetic sources (gap #3).
  • Buy/hold/pass rule (§19.9): label only from ScoringService or explicit human selection; otherwise the fixed sentence "Manual review required before making an investment decision."
  • Bear-case rule (§19.7): 0%-appreciation row always shown.
  • Acknowledgement gate: exports + memo blocked until flagged assumptions acknowledged (flags per §19.4).
  • Client sends: memo = REVIEW_REQUIRED via Outbox (§30). Equity-card use downstream requires consent gates (§18.3) — surfaced on consuming screens.
  • Zoning: claim gate on every claim; verbatim §17.3 disclaimer; Mapbox attribution on plan overlays; no Mapbox/Google tiles as AI-render input; AERIAL_ADU marketing = REVIEW_REQUIRED.
  • No guessing: rent, mortgage balance, forecast scores — missing data blocks or degrades, never fabricates.
  • Fair housing: no protected-class or family-status framing in memo text; memo compliance pass before send (platform ComplianceProvider rule).
