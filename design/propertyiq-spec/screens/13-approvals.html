Spec — 13 · Global Approvals Inbox

Purpose The single surface where every automation across all modules terminates for human sign-off. One card per logical unit of work (One-Approval UX, Wattson Master Brain Part 8 — a hard architectural principle). Nothing consequential ships anywhere in PropertyIQ without passing through here; expired items default to NOT shipping (fail-closed).

Primary users Agent/owner (Graeham-class user). Secondarily: delegated approvers — a TC or assistant granted per-lane approval rights (never global; a team member's Wattson instance can never approve its own REVIEW_REQUIRED output — Part 3).

Entry points Persistent ✓ icon in the top bar of every agent screen; badge = pending count. Deep links from: Command Center content queue, Monday Briefing backlog actions, PropReach campaign wizard ("Publish → Approvals"), Funnel builder (17), SEO console deploy flows (20), Distribution Board nominations, Prospecting drafts, Voice Ops outbound queue. The single interrupt-tier push when an unseen item is about to expire. Mobile: first-class bottom-nav destination ("approvals are the #1 phone task").

Exit points Approve → dispatch via owning module; mints ContentLock for content items; ledger events; card → History. Edit → element-specific edit modal (content) or inline editor (messages) → new version → NEW compliance pass → NEW lock → re-enters as v(n+1). Reject w/ reason → halt group, log, notify owner (on_reject). Defer → re-queue; expiry clock keeps running. View diff (SEO) → overlay → Deploy or back. History link → decision log. Delegation link → delegation panel. Emergency kill switch = Settings (21), not duplicated here.

Layout

Desktop: Header (sitehead) — avatar · "Approvals" · summary "N pending · oldest expires in Xh" · lane chips All / Content / Messages / Spend / SEO (+ Gifts, Postcards, Video as counts require; chips show live counts) · right nav History, Delegation. Main: single-column card stack, oldest-expiry-first (SLA rule). The highest-stakes bundle card renders emphasized (brand border + brand-soft background). Below the stack: an overflow line when >5 card types; the draft's depth-spec info panel is design documentation only — not shipped UI. No left/right rails inside the inbox, no footer. Sticky: header with lane chips pins on scroll.

Mobile (375px): the entire inbox = swipe cards — right approve, left reject (with reason sheet), down defer; tap expands the full card. Lane chips scroll horizontally under the header. Batch buttons collapse into a per-lane action sheet.

States

  • Default: card stack oldest-expiry-first; lane chips with counts.
  • Loading: skeleton cards (3); header counts render last (no fabricated counts).
  • Empty: "Nothing needs your sign-off ✓" + next generation time.
  • Error/degraded (fail-closed): ApprovalRecord service unreachable → full-screen degraded notice, all approve buttons disabled ("Can't verify queue state — nothing will ship until this recovers"). ComplianceProvider down → cards show compliance UNKNOWN, Approve disabled (compliance must pass before send — V0 §14; nothing improvises).
  • Permission-limited (delegate view): only granted lanes visible (others hidden, not greyed); approvals stamped with identity + provenance; no Delegation panel.
  • Mixed-compliance lane: batch button disabled with reason tooltip.
  • Mobile: swipe-card mode; reject ALWAYS requires the reason sheet.

Data fields

group_id, correlation_id string ids (Wattson bundle, Part 8) · lane enum CONTENT · CAMPAIGN · SPEND · MESSAGE · GIFT · SEO_DEPLOY · POSTCARD · VIDEO [BEST GUESS names] · outputs[] step_output payloads w/ previews (owning module) · recommended_action string · expires_at timestamp, default now+48h (Part 8) · status PENDING · APPROVED · REJECTED · DEFERRED · EXPIRED · UNDONE [BEST GUESS enum] · compliance_result pass / block / needs_review + reason (ComplianceProvider) · content_lock_version "ContentLock v2" (PropCast lock registry) · provenance requested_by (Wattson / playbook id / user), approved_by, approved_at (audit log) · consent snapshot (message cards) channel consent + DNC + quiet-hours (check_outbound_contact) · envelope remaining (spend cards) currency, from envelope config · rejection_reason required text.

Rules & compliance

  • Fail-closed everywhere: expired = nothing ships; compliance-unknown = approve disabled; missing approved copy = BLOCKED, never invented.
  • Never-Autonomous List items (any client-facing comm, Reddit posts, GBP review replies, voice price/commitment, cloned voice w/o VoiceIdentity, testimonial w/o ReleaseRecord, spend above cap, contract terms, MLS submission, financial categorization) ALWAYS arrive here — no promotion path exists (MB Part 8).
  • Approve = atomic execution of the bundle; any post-approval edit = new version → new compliance pass → new ContentLock (two governed decisions total: Monday backlog approval + per-piece version approval).
  • Delegation is per-lane, never global; delegated approvals log identity; self-approval by the producing instance is forbidden (Part 3).
  • Sensitive-topic items never appear here — they route to the Outbox/Review Queue (Tab 24) as human handoffs with automation suspended (C1/B1.8).
  • Fair-housing/compliance blocks show the specific rule and a compliant alternative (Wattson refusal pattern).
  • One interrupt-tier push only: expiring-unseen items (all else batches to the morning brief — Tab 21 notification model).
