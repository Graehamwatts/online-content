Screen 17 — Funnel Page & Lead-Magnet Builder (PropCast/PropReach). The owned capture layer behind every piece of content: pick a container from the 13-row matrix (keyword → landing page → lead-magnet PDF), the page + PDF + DM flow generate together from real Stage-2 data, the agent edits slots, and publishing routes through Approvals (Tab 13). Home of the system-wide "⚡ Create funnel" easy button and the UTM auto-scheme. Primary users: agent, marketing coordinator (edit), Wattson (proposes funnels via recommendations).
⚡ The easy button — "Create funnel" lives on EVERY content object
Any video, script, listing, carousel, or news card — anywhere in the system — carries one button: ⚡ Create funnel. One click: the engine picks the matching container (listing video → tour gate · market video → report capture · ADU script → checklist magnet), pre-fills headline/geo/CTA from the content's own facts, inherits its ContentLock lineage, and opens THIS builder with everything filled in for a 30-second edit-and-publish. The reverse button exists too: any funnel page offers "⚡ Create content for this page" → opens a content-engine brief seeded with the page's container type, geo, and performance history.
Entry points that land here pre-filled: ⚡ on any content object · Wattson rec one-click create · Content Review bundle build (Tab 16) when a container needs manual editing · Campaign Manager (Tab 18) "landing destination missing" fix path. Pre-filled arrivals skip to step 3 (see states strip).
UTM auto-scheme — nobody ever types a UTM by hand
utm_source={platform} · utm_medium={organic|paid|email|print|qr} · utm_campaign={contentlock-id} · utm_content={variant} · utm_term={audience-segment}
Generated at publish time per destination, enforced by the distribution layer (a link can't ship without them), resolved back to the content object in the ledger — every click, from a YouTube description to a postcard QR, lands as attributed evidence on the same ContentLock. Short-link mapping stores the full lock identity {content_id, content_lock_id, lock_hash, approved_version_id}.
The loop this closes — Wattson recommendation surfaces (visible in Attribution, Tab 31)
Content → platforms → clicks/leads per piece → recommendations queue:

Every recommendation is one click from done; anything that spends money routes through Approvals first — never auto-spends.

States

  • Default: 3-step wizard (container → mode → edit/preview).
  • Pre-filled (easy button): all slots filled; user lands directly on step 3.
  • Loading: page + PDF generating together — skeleton preview with "generating from {content} facts".
  • Empty (My pages): "No funnel pages yet — every video/listing carries ⚡ Create funnel."
  • Error/degraded (fail-closed): data source missing (no MLS stat for subhead) → slot renders "data unavailable" and blocks publish until edited/removed — never a fabricated number; PDF generation failure → publish blocked with typed reason; hosting deploy failure post-approval → page status DEPLOY_FAILED with retry; identity config missing → hard block (footer cannot render → nothing publishes).
  • Pending approval: page read-only with "In Approvals" banner + link.
  • Permission-limited: coordinator can edit slots; only approval-permitted roles see Publish enabled; footer and pixels locked for everyone.
  • Mobile: wizard variant per Layout.

Data fields

container_type: enum (13 values per matrix), assigned at Stage 2. Page: slug/URL, headline, subhead, hero video URL, CTA copy, mode (BRANDED/UNBRANDED) — container_copy frozen in ContentLock. Footer identity: name, DRE #, brokerage, Fair Housing logo — identity config, read-only. Lead magnet: template id, generated PDF URL, data snapshot + as-of date. DM flow: keyword, dm_copy, follow-up copy, crm_tag, source field propcast_organic_[platform]. Tracking: pixel ids, GA4 id, short link, UTM set — short-link mapping stores lock identity. Lock identity: content_id, content_lock_id, lock_hash, approved_version_id. Lead events: LEAD_CAPTURED / LINK_SCANNED / DOC_DOWNLOADED {content_id, content_lock_id, lock_hash, approved_version_id, contact_id, container_type, timestamp} → Event Ledger (PropFlow/Platform emitters).

Rules & compliance

  • Container copy created after lock ⇒ new approved_version_id + Gate 2 rerun + new ContentLock; the container step may build from locked fields but may never invent new public-facing copy.
  • Footer (agent name, license, brokerage, NAR logo) is locked on branded AND unbranded pages; DRE always from identity config — never hand-typed (the identity.json DRE blocklist applies).
  • Fair Housing gate for lifestyle containers: facts not characterizations; no best/top/worst rankings; no school-quality/demographic proxies; source attribution on every data point; "verify with the source" disclaimer; uniform availability; one-time broker/legal sign-off on the template library.
  • Honest gate copy — no dark patterns; pixel disclosure + DNT/Global Privacy Control respected (Part 5 hard rules).
  • Routing rule: landing page serves search/paid traffic; comment-DM serves organic social — the builder wires both from one container.
  • School/boundary data (lifestyle pages) is user-initiated, identical for all users, disclaimed — no conversion CTA inside the schools block (matrix correction #4).
  • No fabricated stats: every data slot carries source + as-of date or renders unavailable.
