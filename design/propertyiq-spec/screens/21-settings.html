Spec — 21 · Settings Suite & Notifications

Purpose The governance heart of the platform: locked brand identity, the autonomy/permission matrix per playbook step, spend/rate caps with live meters, integration health, channel registry, sequences/templates registry, notification preferences + the in-app notification center, data-retention display — and the kill switch where it can be found in a panic.

Primary users Agent/owner. Admin-scoped panels (delegation grants, promotion sign-off, kill switch) are owner-only; team members get read-only or hidden panels per role.

Entry points ⚙ Settings in the persistent left rail / top nav of every agent screen; notification bell (top bar, app-wide) opens the Notification Center panel; deep links from Approvals (delegation, autonomy promotion), from degraded-integration banners anywhere in the app ("repair task" links), from spend cards (envelope config), from onboarding wizard completion (Tab 23 hands its choices here for later editing).

Exit points Emergency stop → confirmation modal (scope selector) → global halt; integration repair task → provider OAuth flow; autonomy promotion approval → logged to Admin Console; sequences registry → template editor; notification item → the originating screen (ledger deep link); nothing here navigates outside the app except OAuth consents.

Layout

Desktop: Header (sitehead) — avatar · "Settings" · subtitle "Identity · Autonomy · Channels · Integrations · Limits · Notifications" · right nav: ⏻ Emergency stop in crit-red, always visible. Left rail (section nav): Identity & Brand / Automation & Autonomy / Limits & Meters / Integrations / Channels / Sequences & Templates / Lead Sources / Notifications / Data Retention / Calling Hours & Voice / Billing. States

  • Default: overview card grid; degraded integrations surface a warn chip on the overview card.
  • Loading: skeleton meters; never fabricate meter values — meters show "—" until real data arrives.
  • Empty/first-run: unset envelope fields display "not set — nothing autonomous"; unconnected integrations show setup CTAs (mirrors onboarding Tab 23).
  • Error/degraded (fail-closed): meter service down → editing disabled ("can't verify current usage — limits locked"); integration API down → DEGRADED card + downstream-impact list + repair task; policy service unreachable → autonomy-matrix edits disabled (no permission changes without verified state).
  • Emergency-stopped: global red banner app-wide; Settings shows stop scope, who triggered, when; resume owner-only with confirmation.
  • Permission-limited: non-owner sees Identity (read-only), own notification prefs, nothing else by default; delegated admins see granted panels; kill switch + promotion approval strictly owner.
  • Mobile: single-column; matrix h-scrolls; emergency stop persistent in header.

Connector status (connected/degraded/disconnected + expiry + downstream-impact list). Channel rows (provider primary/backup, LAUNCH-REAL/PHASED, gate). Template records (id, version, approval status, BLOCKED flag). Notification classes (interrupt vs batched; per-channel matrix). RetentionClass rows (class → duration → post-expiry behavior). solo_mode boolean.

Rules & compliance

  • Identity is locked: DRE/brokerage/contact read-only from identity.json; the brand tripwire blocks any output containing a DRE on the identity.json blocklist — never render the known-bad legacy number anywhere, including in examples.
  • Loosening permissions requires the promotion flow (all four criteria + logged owner sign-off); tightening is always instant. Never-Autonomous items have no promotion UI at all.
  • No invented spend defaults: envelope fields start null; the UI must state that null = nothing autonomous.
  • Circuit breakers pause + alert, never silently degrade (Part 13: halt, log, notify owner, retry ≤3 only if configured).
  • Rate limits live in ChannelPolicy, not hardcoded (C21) — the UI edits policy records, not module constants.
  • Kill switch: <5s, Temporal-owned, no SIGSTOP; resume owner-only.
  • No module may hardcode DNC, calling-hours, AI-disclosure, Fair Housing, consent, retention, pixel, or rate-limit rules outside the shared services (V0 §14) — this screen is the window onto those services, not a second copy.
  • Every change here writes to the immutable audit log with who/when/before/after.

Cross-links
