What’s actually going wrong

When the brief asks GoHighLevel for “who came in yesterday,” it gets the contacts back newest-first — then it stops the moment it sees the very first contact that’s newer than yesterday. Since there’s almost always someone added today, it stops on contact #1 and counts zero. And it never sets a “don’t go older than yesterday” limit either — so on the rare day it doesn’t stop early, it scoops up your whole database (that’s the 2,000). It needs one bound on each end of the day. That’s the entire bug.

The fix — written & ready

One small change to the contact-counting logic (the same change applies to opportunities). It adds the missing “not older than the window” limit and skips past too-new contacts instead of bailing out:

- if cdt >= end_dt:           # too new?
-     past_window = True       # …then STOP entirely (bug: kills the batch)
-     break
- contacts.append(c)          # …and count everything else, no lower bound (bug)
+ if cdt >= end_dt:           # too new?
+     continue                 # skip it, keep scanning older ones
+ if cdt >= start_dt:         # inside the target day?
+     contacts.append(c)       # count it
+ else:                        # older than the day?
+     past_window = True        # now we can safely stop
+     break
