Today's 7:15 AM run hit the same wall as yesterday: the sandbox-side PAT only has repo scope, so it cannot create .github/workflows/daily-attribution-brief.yml in the repo. Without that workflow file, there's no scheduled job, no GHL pull, no real data. The workflow YAML, the Python pull script, and the SMTP sender script are all sitting in the repo or staged locally — everything is ready except the one file that GitHub blocks unless you have workflow scope on your token. Five minutes of manual work on your end unblocks every future run.

Unblock — do these once

1
Upload the workflow file manually. Go to github.com → online-content → .github/workflows → Add file. Name it daily-attribution-brief.yml. Paste the contents of runbooks/daily-attribution-brief-workflow.yml (already in the repo). Commit to main.
2
Add 4 repo secrets. Repo → Settings → Secrets and variables → Actions → New repository secret. Add: GHL_PIT (value from your local ghl-pit.txt line 1), GHL_LOCATION_ID = 6wuU3haUH7uNeT20E3UZ, GMAIL_USER = your Gmail address used for sending, GMAIL_APP_PASSWORD = a 16-char Gmail app password.
3
(Optional) Upgrade the PAT so I can automate this next time. github.com → Settings → Developer settings → Personal access tokens → Tokens (classic) → Edit the PAT in github-token.txt → check the workflow scope → Update. Once that's done, I can ship workflow files on my own and won't ever ask you to copy-paste a YAML again.
4
Smoke-test the action. Repo → Actions → "Daily Attribution Brief" → Run workflow → leave date blank → Run. You should see a green run within 60 seconds and an email land in your inbox.
