What's actually wrong with this task (the receipt)

.github/workflows/daily-attribution-brief.yml has a real YAML bug: the embedded Node script writes raw HTML starting at column 1 inside a run: | block, which terminates the YAML block scalar early. GitHub's own parser confirms it — the workflow shows up with no name and rejects every workflow_dispatch call:
POST /actions/workflows/daily-attribution-brief.yml/dispatches  →  422 {"message":"Workflow does not have 'workflow_dispatch' trigger","documentation_url":"https://docs.github.com/rest/actions/workflows#create-a-workflow-dispatch-event","status":"422"}

I tried to push a one-line fix this morning and GitHub rejected it: refusing to allow a Personal Access Token to create or update workflow .github/workflows/daily-attribution-brief.yml without 'workflow' scope — by design, the repo token only has repo scope. Only a token with workflow scope (yours to mint) can fix that file. I did not attempt any workaround around that restriction.

Also worth knowing: every prior “GHL pull failed — 401” email this task sent you (Jun 29 – Jul 7) was diagnosing the wrong credential. It was reading the placeholder token in .claude-credentials/ghl-pit.txt, a local file this specific task's design happens to check — not the real GHL_PIT GitHub secret, which has been valid the whole time (see below).
